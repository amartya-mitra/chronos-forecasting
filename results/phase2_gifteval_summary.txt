DATASET NOTE — Decomposition source
  The m4hourly-tsf.arrow file does NOT contain pre-computed trend/seasonal/volatility
  columns for the context window.  The schema is:
      item_id, mode, context (96 pts), target (144 pts), s_first, s_second, s_third
  The 'target' column encodes [trend_fc(48) | seasonal_fc(48) | raw_future(48)] —
  decompositions of the FORECAST window only, which are not usable by PrefixGenerator
  (which requires context-window decompositions as input).

  What was done instead: STL decomposition computed on-the-fly on the 'context'
  column (96 pts) using the same detect_periods + stl_decompose pipeline as SarSim0
  training, with Fix 1a (min_period=6) applied.

  Key distributional difference vs. SarSim0 training:
    SarSim0 context: 512 pts, synthetic, normalised to unit scale
    M4H context:      96 pts, real-world hourly, raw scale (values O(100–10000))
  The prefix was never trained on 96-pt context decompositions at real-world scale.
  This context-length and scale mismatch is a direct contributing factor to the
  attention collapse documented in §4 and §6(c) below.
